Garbage collection

Deleting a tag removes only its manifest; blobs stay on disk until garbage collection. During a collection the registry is restarted read-only: pulls keep working, pushes are rejected. Do not push during it.

Deploying from this registry

Push an image, then create a Project whose image is:

{{ st.image_host }}/<repository>:<tag>
{{ st.image_host }}/<repository>@sha256:<digest>

Prefer the digest form: any registry user can overwrite a tag. No login is needed on the Host; Yanto supplies its internal credential for pulls from {{ st.image_host }} (also for compose files in Git Projects that name it). The Docker daemon treats loopback registries as insecure by default, so plain HTTP works on the Host.

On the Host: docker login {{ st.image_host }}, docker tag app {{ st.image_host }}/app:1, docker push {{ st.image_host }}/app:1.
